Fix 1 • CRIT-01: Margin Accounting & Short-Sale Solvency Enforcement
CRIT-01 Short Sale Solvency & Phantom Cash Injection
Resolved • broker.py

Root Cause & The Vulnerability

In broker.py, fund availability checks were executed exclusively for BUY orders. When opening a short position:

  • Zero cash or margin checks were performed.
  • Gross short sale proceeds were added directly to available cash: self.cash += (fill_size * fill_price) - commission.
  • No initial margin collateral was escrowed.
  • An account with \$1,000 could short \$10,000,000 notional, immediately receive \$10M in cash, and deploy it into other long assets.

What Was Fixed & The Engineering Solution

Implemented comprehensive institutional margin accounting:

  • Configurable Margin Ratio: Added margin_ratio: float = 0.5 (50% Reg T initial margin) to Broker.
  • NAV & Purchasing Power: Added equity property (Cash + Unrealized Book Value) and get_available_cash().
  • Collateral Reservation: Short liabilities reserve size × price × (1 + margin_ratio) from free cash.
  • Order Rejection: Any short sale requiring margin in excess of available cash is rejected (status = 'REJECTED').
Before (Vulnerable broker.py)
# broker.py: Fund checks only for BUY; SELL has zero checks
if order.side == "BUY":
    cost = (fill_size * fill_price) + commission
    if cost > self.cash:
        order.status = "REJECTED"
        return None

# Cash blindly credited without checking margin:
if order.side == "BUY":
    self.cash -= (fill_size * fill_price) + commission
else:  # SELL (short opening gives free cash!)
    self.cash += (fill_size * fill_price) - commission
After (Secured broker.py)
# broker.py: Strict margin and solvency for both sides
if order.side == "BUY":
    if curr_pos_size >= 0:  # Long entry
        required_capital = (fill_size * fill_price) + commission
        if required_capital > self.get_available_cash():
            order.status = "REJECTED"; return None
    else:  # Covering short
        covering_cost = (min(fill_size, abs(curr_pos_size)) * fill_price) + commission
        if covering_cost > self.cash:
            order.status = "REJECTED"; return None
else:  # SELL
    if curr_pos_size <= 0:  # Opening or adding to SHORT
        required_margin = (fill_size * fill_price * self.margin_ratio) + commission
        if required_margin > self.get_available_cash():
            order.status = "REJECTED"; return None

Concrete Example • Over-Leveraged Short Attempt

Scenario: Trader has \$1,000 cash. An aggressive intraday signal triggers an order to SELL (Short) 200 shares of AAPL @ \$100 (Notional Value: \$20,000). Margin ratio is 50% ($0.5$).

Before The Fix (Catastrophic Leverage)

1. Order side is SELL → Broker completely skipped solvency check.
2. Order executed in full: Sold 200 shares @ \$100.
3. Broker credited \$20,000 to cash → Cash became \$21,000!
4. Trader with \$1k was able to buy \$21k of long stock with phantom cash.
5. Result: 20x unconstrained leverage; impossible in real trading.

After The Fix (Institutional Solvency)

1. Broker calculates required initial margin: 200 × $100 × 0.5 = $10,000.
2. Broker checks available unencumbered cash: get_available_cash() = $1,000.
3. Required Margin (\$10,000) > Available Cash (\$1,000).
4. Order is immediately REJECTED.
5. Result: Realistic solvency guaranteed. Verified by test_short_selling_insufficient_margin.

Fix 2 • CRIT-02: Dynamic Universe Retention (Eliminating "Zombie" Positions)
CRIT-02 Active Position Protection in Dynamic Universes
Resolved • data_manager.py & backtester.py

Root Cause & The Vulnerability

When universe_fn(ts) updated the tradable assets (e.g. top 5 momentum stocks):

  • DataManager.load_data evicted every asset not in the new universe list: symbols_to_evict = list(set(old) - set(new)).
  • Backtester.run queried data only for self.current_universe.
  • If the portfolio was holding an open position in an evicted stock, the stock was missing from data.
  • In _process_order: if order.asset not in data: return None → Stop-loss and target exit orders were permanently blocked!
  • In analyzer.py, the position was omitted, causing an instant 100% flash-crash in portfolio valuation.

What Was Fixed & The Engineering Solution

Implemented Active Asset Protection:

  • Protected Cache: Added protected_symbols parameter to DataManager.load_data so open positions and active orders are shielded from cache eviction.
  • Dynamic Tracking Union: On each bar, Backtester.run computes: $$\text{held\_symbols} = \{A \in \text{positions} \mid \text{size} \neq 0\} \cup \{A \in \text{active orders}\}$$
  • Unified Query: Fetches data for current_universe ∪ held_symbols, guaranteeing that stop losses and exits execute even when an asset drops out of the ranking universe.
  • Once closed, the symbol is cleanly evicted on the next refresh cycle.
Before (Evicting Held Assets)
# data_manager.py: Purges any symbol not in new list
def load_data(self, symbols):
    old_symbols = list(self.data_cache.keys())
    symbols_to_evict = list(set(old_symbols) - set(symbols))
    self.clear_cache(symbols_to_evict)  # Evicts open positions!
    self._load_data(symbols)

# backtester.py: Queries only new universe
data = self.data_manager.get_data(self.current_universe, str(ts))
# Held position not in data -> Stop Loss cannot execute!
After (Protected Tracking Union)
# data_manager.py: Protects held symbols
def load_data(self, symbols, protected_symbols=None):
    protected = set(protected_symbols or [])
    keep_symbols = set(symbols) | protected
    symbols_to_evict = list(set(self.data_cache.keys()) - keep_symbols)
    self.clear_cache(symbols_to_evict)
    self._load_data(list(keep_symbols))

# backtester.py: Queries Universe UNION Held Symbols
tracking = list(set(self.current_universe) | held_symbols)
data = self.data_manager.get_data(tracking, str(ts))

Concrete Example • Momentum Rotation with Stop Loss Exit

Scenario: On Day 1, TATAMOTORS is in the top-5 momentum universe. The strategy buys 100 shares @ \$100 with a Stop Loss at \$95. On Day 2, TATAMOTORS momentum drops and it is replaced by RELIANCE in the top 5. On Day 2 at 10:30 AM, TATAMOTORS drops to \$94.

Before The Fix (Zombie Orphan Position)

1. Day 2 universe: ['RELIANCE', ...] (no TATAMOTORS).
2. DataManager purged TATAMOTORS from cache.
3. data dictionary did not contain TATAMOTORS.
4. Stop-loss order @ \$95 checked TATAMOTORS not in data → return None.
5. Stop loss failed to fire; position remained open indefinitely.
6. Analyzer valued position at \$0 → Spurious catastrophic drawdown spike!

After The Fix (Continuous Protection & Clean Exit)

1. Backtester identified open position in TATAMOTORS.
2. TATAMOTORS was passed as protected_symbols → Cache retained.
3. tracking_symbols = Current Universe ∪ {TATAMOTORS}.
4. At 10:30 AM, bar received: Low=\$94 ≤ Stop=\$95.
5. Stop Loss order executed cleanly at \$95; position closed.
6. Result: Realistic exit, accurate PnL, smooth equity curve. Verified by test_dynamic_universe_retains_held_positions.

Fix 3 • CRIT-04: Institutional Risk Sizing Reform
CRIT-04 Fixed Risk Sizer Reformed to Stop-Distance & Portfolio NAV
Resolved • sizer.py

Root Cause & The Vulnerability

In FixedRiskPercentSizer:

  • The method signature accepted stop_loss_price, but the formula completely ignored it: int((cash * risk_percent / 100) / entry_price).
  • This was Capital Allocation (allocating 1% of cash), NOT Risk Sizing!
  • A stock with a \$0.50 stop was sized identically to a stock with a \$50 stop, taking on 100x more tail risk on wider stops.
  • Sized against broker.cash instead of NAV: as positions were deployed, trade sizes decayed exponentially.

What Was Fixed & The Engineering Solution

Reformed to quantitative risk management standards:

  • Risk-to-Stop Sizing: Computes risk per share $\vert\text{entry} - \text{stop}\vert$ and sizes based on exact monetary risk: $$\text{Size} = \left\lfloor \frac{\text{Equity} \times (\text{Risk\%} / 100)}{\vert\text{Entry Price} - \text{Stop Loss Price}\vert} \right\rfloor$$
  • NAV Capital Base: Uses total portfolio Net Asset Value (broker.equity), preventing artificial position decay.
  • Graceful Fallback: If no stop loss is passed, safely falls back to equity allocation.
  • Purchasing Power Guardrail: Capped at affordable shares based on available purchasing power.
Before (Ignored Stop Loss & Used Depleting Cash)
class FixedRiskPercentSizer(Sizer):
    def get_size(self, broker, asset, entry_price, stop_loss_price, side, **kwargs):
        # Ignored stop_loss_price completely!
        # Divided by entry_price instead of risk per share:
        cash_to_risk = broker.cash * (self.risk_percent / 100)
        return int(cash_to_risk / entry_price)
After (True Risk-to-Stop & Portfolio Equity)
class FixedRiskPercentSizer(Sizer):
    def get_size(self, broker, asset, entry_price, stop_loss_price=None, side="BUY", **kwargs):
        equity = getattr(broker, "equity", broker.cash)
        capital_to_risk = equity * (self.risk_percent / 100.0)

        if stop_loss_price is not None and stop_loss_price > 0:
            risk_per_share = abs(entry_price - stop_loss_price)
            raw_size = int(capital_to_risk / risk_per_share)
        else:
            raw_size = int(capital_to_risk / entry_price)
        # Capped at available funds to guarantee execution
        return max(0, min(raw_size, max_affordable))

Concrete Example • Risk-to-Stop Sizing in Action

Scenario: Trader has \$10,000 portfolio equity. The strategy enters a trade with 1.0% risk (monetary risk budget = \$100). Stock entry is \$100.00 with a planned stop loss at \$98.00 (price risk per share = \$2.00).

Before The Fix (Grossly Undersized)

1. Sizer computed: $10,000 × 1% = $100.
2. Divided by entry price: $100 / $100.00 = 1 share.
3. Total position taken: 1 share (\$100 invested).
4. If stop hit at \$98: Actual loss was only \$2.00 (0.02% risk!).
5. Result: Position was 50x undersized; failed to capture intended alpha.

After The Fix (Mathematically Sound Risk Model)

1. Sizer computes risk budget: $10,000 × 1% = $100.
2. Computes risk per share: |$100.00 - $98.00| = $2.00.
3. Sizes position: $100 / $2.00 = 50 shares.
4. Total position taken: 50 shares (\$5,000 invested).
5. If stop hit at \$98: Actual loss is exactly \$100.00 (precisely 1.0% risk).
6. Result: True institutional risk management. Verified by test_fixed_risk_sizer_with_stop_loss.
