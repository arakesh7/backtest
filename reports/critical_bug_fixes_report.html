Detailed Re-examination: CSVDataLoader Schema & Timezone

Finding: The initial audit flag regarding an OHLCV column inversion in CSVDataLoader was a false alarm. data_manager.py is completely correct and has been preserved in its original form.

  • Column Ordering: In pandas, pd.read_csv(file_path, usecols=['open', 'high', 'low', 'close', 'volume', 'ts']) does not reorder columns to match the usecols list. Instead, pandas strictly preserves the column order from the physical CSV header on disk (ts, open, high, low, close, volume). As verified on actual data, the resulting DataFrame columns were ['ts', 'open', 'high', 'low', 'close', 'volume'] all along.
  • Timezone Conversion: The underlying raw CSV files record timestamps in UTC (e.g. 03:45:00 UTC). The original conversion tz_localize('UTC').dt.tz_convert('Asia/Kolkata') converts 03:45:00 UTC to 09:15:00 IST (Indian market open). This conversion was intentional, accurate, and essential.

Fix 1

Recency-Indexed Circular Buffer Slicing (bar[0] = Latest, bar[-1] = Previous)

File: history.py

Problem: Slicing history[:] in the original code used idxs = (self.head + np.arange(start, stop, step)) % self.size. Because of the forward addition (+), slicing marched into uninitialized buffer slots (None) and jumped to the oldest cycle bar rather than stepping backward in time.

Before (history.py:33-37)
elif isinstance(key, slice):
    start, stop, step = key.indices(self.count)
    # Forward stepping (+):
    idxs = (self.head + np.arange(start, stop, step)) % self.size
    return self.data[idxs]
# Produced corrupted sequence: ['b4', 'b0', 'b1', 'b2', 'b3']
After (Recency Stepping Backward from Head)
elif isinstance(key, slice):
    if self.count == 0:
        return np.empty(0, dtype=object)
    start, stop, step = key.indices(self.count)
    # Step backward from head: 0 = latest (head), 1 = prev (head - 1)...
    idxs = (self.head - np.arange(start, stop, step)) % self.size
    return self.data[idxs]
Outcome:
  • bar[0] returns the latest bar (current bar at head)
  • bar[-1] returns the bar before it (1 bar ago)
  • bar[-2] returns 2 bars before it
  • bar[:] returns [latest, 1_bar_before, 2_bars_before, ..., oldest] with zero uninitialized None elements.
Fix 2

Inverted Cash Flow & Position Flipping Overhaul

Files: order.py & broker.py

Problem: On partial sales (Long 10 → Sell 5 @ 120), Position.update returned closed = -5. In broker.py, close_value = closed * price = -600, which deducted $600 from cash instead of crediting it (cash plummeted from 9,000 to 8,400 upon taking profit!). Furthermore, flipping positions corrupted the cost basis.

Before (broker.py & order.py)
# broker.py:
open_value = opened * fill_price
close_value = closed * fill_price
self.cash += close_value  # (if closed was negative, debited cash!)
self.cash -= open_value + commission

# order.py:
else:  # decreasing
    opened, closed = 0, size  # (size was negative!)
After (Universal Invariant & Pure Transitions)
# broker.py:
if order.side == "BUY":
    self.cash -= (fill_size * fill_price) + commission
else:  # SELL
    self.cash += (fill_size * fill_price) - commission

# order.py Position.update():
elif (old_size > 0 and new_size >= 0) or (old_size < 0 and new_size <= 0):
    opened, closed = 0, abs(size) # clean reduction
else:  # Position flip (e.g. Long -> Short)
    closed, opened = abs(old_size), abs(new_size)
    self.avg_price = price # establish new entry price
Outcome: Selling 5 shares @ 120 increases cash from $9,000 to $9,600 (+600). Flipping to short -5 shares @ 120 sets cash to $10,800 (+1,800) and resets short entry price to $120. Covering shorts debits cash accurately.
Fix 3

Execution Model Partial Fill Overfilling Prevention

File: execution_model.py

Problem: SimpleExecutionModel.execute() returned fill_price, order.size. When an order was partially filled in bar 1 and retried in bar 2, the model re-executed the original full size, resulting in severe over-filling (140%+ of intended size).

Before (execution_model.py:28)
def execute(self, price, order, data_bar):
    fill_price = self.slippage_model.calculate_slippage(order, price)
    return fill_price, order.size
After (execution_model.py:28)
def execute(self, price, order, data_bar):
    fill_price = self.slippage_model.calculate_slippage(order, price)
    return fill_price, order.remaining_size
Outcome: Partially filled orders now fill only their true remaining quantity without size inflation.

File: strategy.py

Problem: In Strategy.next(), a global all_warmed_up gate aborted execution across ALL symbols if any single asset in the universe had fewer bars than bar_history.size. Newly listed assets or dynamic universe entrants caused the engine to freeze across all assets.

Before (strategy.py:40-54)

self.on_data(ts, data)
Outcome: Ready symbols can execute strategies and existing positions can be managed and closed at EOD without being paralyzed by unready universe members.
